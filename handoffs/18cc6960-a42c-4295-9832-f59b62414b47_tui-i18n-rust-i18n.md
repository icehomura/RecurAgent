## 1. What the user decided (do not re-litigate)

- **Framework: `rust-i18n` 4.2.4** — chosen over `fluent-templates`/`i18n-embed`.
- **Key convention: `{module}_{slug}`** (e.g. `login_flow_logout_absent`),
  **not** the English source text. The user overrode my recommendation of the
  rust-i18n-idiomatic literal-as-key.
- **Machine prefixes (`git:`, `ctx:`, `think:`, `agents:`, `session:`, `tok`)
  are optional translation keys**, to be left as reserved hooks for now.
- **First slice is `src/interactive/login_flow.rs`** (I chose; 20 strings).
- **Symbols must be handled separately from prose**, by a dedicated assembly
  function, never baked into a translated string.

### The consequence of symbolic keys the user accepted

A missing key renders **the key itself** (`login_flow_logout_absent`), not
English. There is no silent fallback. That is why `scripts/check_i18n_keys.py`
is mandatory rather than nice-to-have — it is the only thing stopping an
omission reaching a user's screen as an identifier.

## 3. The bug the first compile found — READ THIS

```
error[E0433]: cannot find `_rust_i18n_t` in the crate root
```

`t!` expands to a reference to **`crate::_rust_i18n_t`**, and only the `i18n!`
invocation generates that item. I had put `i18n!` inside `src/i18n.rs`, which
left every `t!` in the crate unable to resolve it. **Fixed:** the registration
now lives at the crate root in `src/lib.rs`, with a comment explaining why, and
`src/i18n.rs` carries a note not to move it back.

This is a real constraint of the crate, not a workaround — worth preserving the
comment when someone "tidies up" the module layout.

### Pipeline for the next slice (ast-grep carries steps 1 and 5)

1. `ast_grep` enumerate per construction shape (`format!`, `push_str`,
   `Line::from`, `Span::raw`, `Text::new`, `const $N: &str = $V`).
2. Classify translatable vs not — **semantic, ast-grep cannot help**. Applied to
   `status_line.rs` it showed `format!("${:.3}")` and `format!("{} tok")` are
   structurally identical while only one is translatable.
3. Assign `{module}_{slug}`; collisions get a short hash. **Append-only registry,
   never renumber.**
4. Add to `locales/messages.yml`.
5. `ast_edit` — one op per distinct literal, staged → diff → atomic apply. Note
   `ast_edit` ops are 1:1 per pattern, so ~2,700 ops if done repo-wide.
6. Hand-fix placeholder sites (~873 contain `{...}`): `{n}` → `%{n}` **and** the
   call site must pass `n = <expr>`. ast-grep cannot derive the placeholder name
   from inside a string literal, so these are one hand-written op per shape.

### The hard rules, paid for already

- **A glyph must never enter a translated string.** `StatusSegment::render_with_chrome`
  renders each segment in three tiers (nerd icon / portable symbol / plain
  ASCII). A glyph inside the literal needs 3 translations per locale instead of
  1, translators drop or mangle private-use codepoints, and it breaks the
  `Ascii` preset's `is_ascii()` assertion. The assembly function owns the
  concatenation.
- **Width is double for CJK.** `unicode_width` everywhere; never `str::len()`,
  and layout tests must run in both locales.
- **Never translate protocol identifiers** (`"allow-once"`, `"end_turn"`,
  `"ra.dag.scheduler.v1"`), in either setting. Same line as `output_language`.
