is mandatory rather than nice-to-have — it is the only thing stopping an
omission reaching a user's screen as an identifier.

## 3. The bug the first compile found — READ THIS

```
error[E0433]: cannot find `_rust_i18n_t` in the crate root
```

`t!` expands to a reference to **`crate::_rust_i18n_t`**, and only the `i18n!`
invocation generates that item. I had put `i18n!` inside `src/i18n.rs`, which
left every `t!` in the crate unable to resolve it. **Fixed:** the registration
now lives at the crate root in `src/lib.rs`, with a comment explaining why, and
`src/i18n.rs` carries a note not to move it back.

This is a real constraint of the crate, not a workaround — worth preserving the
comment when someone "tidies up" the module layout.

### Pipeline for the next slice (ast-grep carries steps 1 and 5)

1. `ast_grep` enumerate per construction shape (`format!`, `push_str`,
   `Line::from`, `Span::raw`, `Text::new`, `const $N: &str = $V`).
2. Classify translatable vs not — **semantic, ast-grep cannot help**. Applied to
   `status_line.rs` it showed `format!("${:.3}")` and `format!("{} tok")` are
   structurally identical while only one is translatable.
3. Assign `{module}_{slug}`; collisions get a short hash. **Append-only registry,
   never renumber.**
4. Add to `locales/messages.yml`.
5. `ast_edit` — one op per distinct literal, staged → diff → atomic apply. Note
   `ast_edit` ops are 1:1 per pattern, so ~2,700 ops if done repo-wide.
6. Hand-fix placeholder sites (~873 contain `{...}`): `{n}` → `%{n}` **and** the
   call site must pass `n = <expr>`. ast-grep cannot derive the placeholder name
   from inside a string literal, so these are one hand-written op per shape.

### The hard rules, paid for already

- **A glyph must never enter a translated string.** `StatusSegment::render_with_chrome`
  renders each segment in three tiers (nerd icon / portable symbol / plain
  ASCII). A glyph inside the literal needs 3 translations per locale instead of
  1, translators drop or mangle private-use codepoints, and it breaks the
  `Ascii` preset's `is_ascii()` assertion. The assembly function owns the
  concatenation.
- **Width is double for CJK.** `unicode_width` everywhere; never `str::len()`,
  and layout tests must run in both locales.
- **Never translate protocol identifiers** (`"allow-once"`, `"end_turn"`,
  `"ra.dag.scheduler.v1"`), in either setting. Same line as `output_language`.

- No file reservation was taken for this work.
- **SHELL GOTCHA, cost three wasted runs: the bash heredoc in this environment
  eats backslashes.** `<<'PY'` is quoted, so nothing *should* expand, but
  `\\` arrives at Python as `\` regardless. It silently corrupted
  `re.compile(r'[^\x00-\x7F]')` (reported 8458 bogus CJK strings),

  `re`); or pass a resolved path via argv (`cygpath -w /tmp/x`) rather than
  embedding it.
- **`/tmp` is a git-bash virtual path and native Windows Python cannot see it.**
  Copy via stdin, or resolve with `cygpath -w` first. Redirecting `< /tmp/log`
  onto a heredoc-fed `python3 -` replaces the script with the log — that failed

The first `cargo test --locked --lib tree_ui` attempt failed during **compilation**
with

    error: could not compile `recur_agent` (lib test)
    Caused by: process didn't exit successfully: rustc ... --test ...
      (exit code: 0xc0000409, STATUS_STACK_BUFFER_OVERRUN)

It is **not reproducible**: `cargo test --locked --lib i18n` immediately after
passed (10/10), and `cargo test --locked --lib tree_ui` then passed (5/5). Same
target, same source, minutes apart.

**Diagnosis (do not re-derive this):** rustc's own stack overflows in
`rustc_monomorphize::collect_and_partition_mono_items` — a recursive walk whose
depth scales with the crate's total monomorphization, so it is a function of
how much code the crate holds, not of any one edit. This repo has hit it before:
`.ra/handoffs/handoff_150a32d6-eac0-46d1-b848-59528fe831df.md` §3.3 records the
same signature from `cargo build --release --locked --bin ra` and notes the
retry path was TBD.

`.cargo/config.toml` already carries both mitigations and explains why they do
not cover this case:
- `RUST_MIN_STACK = 16777216` — sizes threads *spawned* by a process, so it
  covers libtest test threads and never rustc's own main thread;
- `[target.x86_64-pc-windows-msvc] rustflags = ["-C", "link-arg=/STACK:8388608"]`
  — a **linker** flag for the built binary, which does nothing for the `rustc`
  process doing the compiling.

So the gap is rustc's own PE StackReserve on Windows, and the practical response
is: **retry** — and if it persists, it is a crate-size problem to raise with the
whole team, not something a single slice can fix. Do not chase it into LTO
settings or codegen-units as part of a localization slice.

### Lesson 1 — the staged-diff review rejected a reward-hacking rewrite

The first pass-1 proposal used **bare string literals as patterns**, and 3 of
them also matched inside the test module, turning

    assert_eq!(omfg(...).status, "Usage: /omfg <complaint about model behavior>")
into
    assert_eq!(omfg(...).status, t!("workspace_omfg_usage"))

That is a **tautological test**: `status` is produced by `t!` at the call site, so
the assertion compares the catalogue to itself and can no longer fail. It is the
named pattern in `AGENTS.md`. The proposal was **rejected before writing**
(explicitly, `action=reject`) and re-staged with context-bearing patterns —
`Report::status("...")`, `String::from("...")`, `listing("Recent memories", ...)`
— which exist only in product code. Both applied passes touch **zero** test
lines; verify that on any future slice by reading the diff for `@@` hunks past
the `#[cfg(test)]` line.

### Lesson 2 — the orphan direction caught keys I dropped

Three `/handoff` keys (`workspace_handoff_card/_ok/_err`) were written into the
catalogue and planned, but silently omitted when the op list was transcribed.
The gate's **catalogue → source** direction failed precisely on them. Without
that check they would have shipped translated, reviewed, paid for and dead.
Treat a gate failure here as a real finding about your own work, not as noise.

### Two call-site shapes that must not be half-replaced

- `write!`/`writeln!(f, "<fmt>", a, b, c)` **cannot** have only the format string
  swapped — the trailing args become unused and it fails to compile. Replace the
  whole call: `write!(f, "{}", t!(...))`.
- `t!` yields `Cow<str>`, so `push_str(...)` and `&str` parameters need
  `&t!(...)`. `impl Into<String>` parameters (`Report::status`, `Report::card`)
  take the `Cow` directly — no `&`, no `.to_string()`.

### Smaller notes

- `MEMORY_USAGE` was a `const`; `t!` is not const-evaluable, so it became
  `fn memory_usage() -> String` and its three call sites (two product, one test)
  moved with it. That test edit is an *adaptation* to a signature change, not a
  tautology — the distinction is the point.
- `{other:?}` (Debug) quoted its value. The quotes were moved **into** the
  template (`"...subcommand \"%{other}\""`) so the rendered English stays
  byte-identical while the call site passes Display. Never let a localization
  change the English output silently.
- Glyph policy held: `✅`/`⏸️` stay in the code and only the word is translated
  (`format!("✅ {}", t!(...))`); card emoji that are part of a heading line are
  duplicated verbatim in both locales deliberately.
- The commit message contains a shell-mangled word: backticks around `const` were
  command-substituted by bash and the word vanished. Cosmetic, but quote commit
  bodies with single quotes or heredocs from now on.
