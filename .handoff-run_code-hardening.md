## Done — and how each was verified

**JS layer was driven directly with a stub host** (`node -e` harness that spawns
`assets/ptc_sdk.js`, answers `{id,tool,args}` and reports the terminal message). Observed
results:

1. **Wrapper args (P0-1/P0-2).** `sdk.read/grep/find/ls` now accept positional *or* an
   options object, and the object form is forwarded verbatim, so `offset`/`limit`/
   `hashline`/`encoding`/`glob`/`context` take effect instead of being silently dropped.
   `sdk.ls()` (bare) and `sdk.ls({limit:3})` also work. Verified: `read({path,limit})` →
   host received `{"path","limit"}`; `find("*.rs",{limit:3})` → `{"pattern","limit"}`;
   `ls({limit:3})` → `{"limit":3}`; `ls({path:5})` → clear error.
2. **stdout cannot corrupt the protocol (P1-2).** Protocol writes go through a handle
   captured before the program runs; program/dependency `process.stdout.write` is
   redirected to stderr as `[ptc:stdout] ...`. Verified: a deliberate write (and even
   clobbering `process.stdout.write`) leaves the run successful with zero stray protocol
   lines.
3. **`process.exit` (P1-1).** Refused with an actionable `PTC_EXIT` error, plus an `exit`
   backstop and `uncaughtException`/`unhandledRejection` handlers. Verified: no more
   `PTC_EOF`.
4. **Accurate stacks (P1-3).** The wrapper line offset is *measured* at startup, not
   assumed, and `<anonymous>` frames are rebased to `ptc-program:N:M`. Verified: a throw
   on the program's line 3 reports `ptc-program:3:7`. Host renders program frames first,
   falls back to SDK frames, drops node internals.
5. **Real process sandbox (P0-3).** When the runtime supports it, the child is spawned
   under Node's permission model with `--allow-fs-read=<scratch>,<cwd>,<workspace roots>`
   and no write/`child_process` permission. Verified on Node v22.23.2 (Windows):
   `execSync` → `ERR_ACCESS_DENIED`, write → `ERR_ACCESS_DENIED`, a sibling of an allowed
   dir → `ERR_ACCESS_DENIED`, parent-dir listing → `ERR_ACCESS_DENIED`, allowed dir still
   readable. The mode actually obtained is reported as `details.sandbox`
   (`node-permission` | `unavailable` | `disabled`), and `PTC_SANDBOX=off` /
   `RunCodeTool::with_sandbox(false)` opt out explicitly.

Also: protocol parse errors now include the offending bytes (`protocol_snippet`), and the
module docs were corrected — the old header claimed the SDK "never exposes raw `fs` or
`child_process`", which was false (dynamic `import()` reached both); it now documents the
two real layers and the fallback.
